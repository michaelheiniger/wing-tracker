# 1. Record architecture decisions

Date: 2026-10-11

## Status

Accepted

## Context

The project is long-lived and will grow web and mobile versions. Reasons behind structural choices get lost as the code evolves.

## Decision

We record architectural decisions as ADRs in `docs/adr/` using the Nygard format, and treat them as binding constraints. The rules are in [README.md](README.md).

## Consequences

Decisions stay discoverable and challengeable. Every architectural change costs a small documentation step.
